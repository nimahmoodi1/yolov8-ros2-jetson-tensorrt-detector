# Security policy

For ordinary bugs, use GitHub Issues.

For a vulnerability that could expose host data, execute unintended commands,
break container isolation, or create unsafe robot behavior, avoid publishing
exploit details in a public issue.

Contact the repository maintainer privately using the contact information on
the maintainer's GitHub profile.

Include:

- affected version;
- deployment mode (standalone or Docker);
- JetPack/L4T version where relevant;
- minimal reproducer;
- expected behavior;
- observed behavior.

Do not include passwords, access tokens, private keys, or unrelated device
identifiers.
